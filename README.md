# 旅途密令

一个面向 8 人旅行的随机任务网页应用。密令仅保存在本人手机；加入同一个 6 位数字房间后，在线状态、得分、出勤和每日复盘会实时同步。无网络时仍可使用本机模式。

仓库同时包含一套独立的微信小游戏版本“游侠密令”，位于 [`wechat-minigame/`](wechat-minigame/)。小游戏内置 100 条安全任务，并为每个新房间分配一条玩家自创隐藏任务；原网页文件和二维码保持不变。

## 简化规则

1. 每人最多保留 3 个任务抽取额度，每次使用后 6 小时恢复。
2. 任务抽出后只能完成或放弃，2 小时后自动超时。
3. 任务按难度固定为 1、2、3 分。
4. 完成后说“计成”，由一名在场玩家确认。
5. 放弃、超时或越过安全边界均为 0 分。
6. 每日复盘时分享当日记录，全员投票选一个“最佳妙计”加 1 分。
7. 总榜优先按场均分排序，兼顾中途加入或提前离开的玩家。

## 联机房间

1. 第一位玩家点顶部房间按钮，选择“创建房间”。
2. 复制邀请链接发到微信群，链接会自动带入 6 位房间号。
3. 每个房间最多 8 人，系统自动分配 A–H 代号。
4. 密令内容不会同步；任务完成并选择见证人后，只同步分数。
5. 断网时得分会先保存本机，恢复连接后自动补传；同一任务不会重复加分。

## 本地运行

在本目录启动任意静态服务器，例如：

```bash
python3 -m http.server 4173
```

然后打开 `http://localhost:4173`。

## 公网发布

本项目通过 GitHub Pages 发布。仓库 `main` 分支更新后，线上网站会自动重新发布。

## Supabase 配置

1. 新建 Supabase 项目。
2. 在 SQL Editor 执行 [`supabase/schema.sql`](supabase/schema.sql)。
3. 将 Project URL 和 publishable/anon key 填入 `supabase-config.js`。
4. 提交并推送后，GitHub Pages 即可使用联机房间。

`anonKey` 本来就是给浏览器公开使用的密钥。数据表已开启 RLS 且不授予网页直接读写权限；计分通过设备随机凭证和受限函数完成。

所有个人记录保存在各自手机浏览器的 `localStorage` 中。更换手机或清除微信浏览器数据前，应在“设置”中导出记录。
